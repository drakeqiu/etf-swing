# ETF 波段量化项目需求

## 1. 目的

搭建一个可复现、可测试的单 ETF 日线回测项目骨架，为后续 ETF 波段策略研究提供数据获取、复权、回测和结果导出流程。当前交付聚焦工程骨架，不把示例信号误当成已确认的投资策略。

## 2. 目标与边界

### 目标

- 使用现有 `uv` 项目与 Python 3.14 环境管理依赖。
- 按 PEP 8 风格编写代码；使用 Ruff lint/format、pytest、mypy 和 pyright。
- 使用 AmazingData SDK 获取 ETF 日线行情和前复权因子。
- 使用 `backtesting.py` 对单只 ETF 执行日线回测。
- 本地缓存 K 线 CSV，允许显式刷新；不在普通读取时隐式绕过缓存。
- 结果输出机器可读 JSON、权益曲线 CSV、交易记录 CSV。
- 使用离线测试覆盖四个已确认的 seam，测试不得访问真实账号或网络。

### 当前不做

- 多标的组合、仓位再平衡、跨标的资金管理。
- 实盘交易、下单、券商连接或交易信号推送。
- 完整的左侧/右侧/震荡三态交易策略定稿及其投资有效性结论。
- Notebook 作为唯一业务入口。

SMA 示例策略只用于验证端到端数据与回测管线，不代表已经批准的最终策略，也不构成投资建议。

## 3. 已确认需求

### 3.1 项目与命令行

- 保留仓库现有 `uv init` 结构和已配置的 AmazingData、`tgw` 本地 wheel、pyright 等依赖配置。
- 项目提供命令行入口；刷新行情时自动从项目根目录 `.env` 加载登录信息，不要求调用者指定 env-file。
- 认证只在命令启动时由 AmazingData SDK 完成；单元测试不读取凭据、不登录、不访问网络。
- `.env` 属于本机秘密配置，必须纳入 Git 忽略规则，文档不得记录真实凭据。

### 3.2 标的与行情

- 一次回测只处理一个场内 ETF；默认标的是 `563360`，可由命令行指定单一标的。
- 使用 AmazingData 的 ETF 证券类型 `EXTRA_ETF`、日线周期 `Period.day`。标的代码与 SDK 代码格式的对应关系通过 SDK 的 `EXTRA_ETF` 代码表解析，不硬编码未经验证的后缀。
- 通过因子数据进行前复权。复权比例为“当日后复权因子 / 数据区间最新后复权因子”；对 OHLC 同比例调整，Volume 保持原值。该 OHLC 扩展是本项目约定，不应描述为 SDK 默认行为。
- 缺少因子或行情/因子日期不能严格匹配时，显式报错，不静默填充或用未复权数据继续回测。
- K 线使用项目管理的本地 CSV 缓存；缓存目录加入 Git 忽略。普通读取要求缓存完整覆盖所请求的日期区间，缓存缺失或覆盖不足时明确报错；只有显式刷新参数才请求新行情。若 AmazingData 因子接口提供本地缓存能力，可使用其 SDK 缓存。
- 转换成 `backtesting.py` 所需的 DataFrame：DatetimeIndex，以及 `Open`、`High`、`Low`、`Close`、`Volume` 列。

### 3.3 示例策略与资金

- 示例策略使用日线 SMA(20)/SMA(60)：快线高于慢线时持有，否则空仓。
- 收盘时形成信号，下一根日线 bar 执行，避免用当日收盘信号假设可按同一收盘价成交。
- 仅做多，不杠杆；信号开启时尽可能使用可用资金，关闭时平仓。下单数量向下取整至 100 份，未使用现金保留为现金。
- 初始资金为人民币 100,000 元。

### 3.4 成本模型

- 单边佣金率为万分之 0.5（`0.00005`），每次成交最低佣金人民币 0.1 元；开仓和平仓均按各自成交计佣金。
- `backtesting.py` 佣金使用可调用规则表达比例费率与最低收费。
- 另设 `spread=0.0005`（5 bp，即 0.05%）作为 `backtesting.py` 的固定 spread 参数值，必须可配置并在产物/文档中明示；它是框架成本假设，不是 563360 的实测点差或单边滑点。

### 3.5 结果与指标

- 导出 JSON：回测指标与运行参数，包括总收益、Profit Factor、最大回撤、交易次数、平均持仓周期、标的、日期范围、策略参数、初始资金、佣金与 spread 假设。
- 平均持仓周期仅统计已平仓交易，按交易日 bar 数计算，输出中注明单位。
- 没有亏损交易、导致 Profit Factor 无法定义时，JSON 中该字段输出 `null`。
- 导出权益曲线 CSV 与交易记录 CSV。
- 输出数值应来自同一次回测结果，不由文档或测试伪造。

## 4. 质量属性与工程约束

- 所有项目文档使用中文。
- 代码遵循 PEP 8，行宽沿用现有 Ruff 79 字符配置。
- `ruff check`、`ruff format --check`、pytest、mypy、pyright 应能覆盖项目源码与测试。
- 数据变换和回测逻辑应与真实 SDK 登录/网络隔离，便于确定性测试。
- 日线时间、数据区间、复权参考日期、缓存命中/刷新状态应可追溯。

## 5. 已确认的测试验收 seam

1. **复权纯变换**：验证 OHLC 比例调整、Volume 不变；缺失因子和日期错位必须失败。
2. **佣金与回测成交**：验证费率与最低佣金行为，并验证 backtesting.py 开仓、平仓均计入佣金。
3. **数据适配器与缓存**：使用假数据提供器验证代码映射、完整区间缓存命中、缓存覆盖不足时失败以及显式刷新，不调用真实 SDK/网络。
4. **CLI 端到端**：输入确定性合成日线数据，执行回测并验证 JSON、权益曲线 CSV、交易 CSV 及关键指标字段；验证平均持仓周期单位和无亏损交易时 Profit Factor 为 `null`。

## 6. 待实施前确认/需在适配时验证

这些是工程细节，不应通过猜测写成既定事实：

- 本机 AmazingData SDK 中 `EXTRA_ETF` 代码表的实际格式，以及 `563360` 的可解析映射。
- 当前安装版本 SDK 的认证、日线和因子查询精确方法签名及返回字段。
- 日线数据是否包含停牌/缺失日期，以及 SDK 因子日期与 K 线日期的实际对齐规则。
- `backtesting.py` 当前 Python 3.14 环境的运行时兼容性。
- 缓存文件命名、默认缓存目录和 CLI 参数名称可在实现时按现有项目惯例确定，但必须保持可预测、可文档化。

## 7. 验收标准

- 无 `.env` 凭据也可运行全部测试，且测试不会向网络发请求。
- 假数据可以贯通行情适配、复权、回测和结果导出。
- 数据/因子不匹配会明确失败；缓存缺失或未覆盖完整请求区间时普通读取明确失败，只有显式刷新才重新获取行情。
- 佣金最低收费、双边计费与 spread 假设均明确表达并有测试。
- 输出文件包含本需求列明的核心结果与运行参数。
- CLI 和数据使用方式、成本假设、缓存行为、单标的边界及示例策略非最终性质均有中文说明。
