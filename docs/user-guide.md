# 使用指南：理解参数、策略与回测结果

本指南补充说明常用参数、示例策略和结果文件。环境安装、凭据配置及首次运行命令见 [README 快速开始](../README.md#快速开始)，避免在两处维护同一套步骤。

> **项目边界：**这是一个单只 ETF 的日线回测工程骨架，不是已验证有效的波段策略。它不会下实盘订单、连接券商或推送买卖信号；示例规则仅用于检查回测流程，不构成投资建议。

## 1. 运行前确认

- 在项目仓库根目录操作，即能看到 `pyproject.toml` 的目录。
- 项目使用 Python 3.14 和 `uv`；本地 wheel 位于 `wheels/`，安装依赖时不要删除。
- 刷新行情需要 AmazingData 本机环境、有效账号及行情权限；普通缓存回测不需要登录。
- `.env`、`data/cache/` 和 `results/` 都是本机数据，不要提交到 Git。真实凭据不要贴到聊天或写进文档。

README 中的刷新命令会把行情及配套数据写入 `data/cache/`。不带 `--refresh` 的运行只读缓存，不会联网或自动补数据；若目标日期超出缓存覆盖范围，需显式刷新对应区间。

## 2. 常用命令参数

| 参数 | 用途 | 默认值或要求 |
| --- | --- | --- |
| `--symbol` | 指定单只 ETF | `563360` |
| `--start` | 回测起始日期 | 必填，`YYYY-MM-DD` |
| `--end` | 回测结束日期 | 必填，`YYYY-MM-DD` |
| `--refresh` | 明确刷新行情、因子和交易日历缓存 | 默认不刷新 |
| `--spread` | 修改回测框架使用的固定 spread 成本假设 | `0.0005`，也就是 0.05% |
| `--cache-dir` | 指定行情缓存目录 | `data/cache/` |
| `--output-dir` | 指定结果输出目录 | `results/` |

例如，将结果放到另一个目录并使用不同的 spread 假设：

```sh
uv run etf-swing \
  --symbol 563360 \
  --start 2024-01-01 \
  --end 2025-12-31 \
  --spread 0.001 \
  --output-dir results/test-run
```

起始日期不能晚于结束日期。若缓存不完整或覆盖范围不足，普通运行会报错；确认标的和日期后，再按 README 的刷新方式更新缓存。

## 3. 当前实际运行的是什么策略？

项目当前用 SMA(20/60) 做示例。SMA（简单移动平均线）是最近若干交易日收盘价的算术平均值。

| 规则 | 行为 |
| --- | --- |
| 快线 | 最近 20 个交易日收盘价的平均值。 |
| 慢线 | 最近 60 个交易日收盘价的平均值。 |
| 快线高于慢线 | 从空仓转为持有 ETF；已有持仓时继续持有。 |
| 快线不高于慢线 | 有持仓则平仓；已空仓则继续空仓。 |
| 仓位方向 | 只做多，不做空、不加杠杆；持仓只能继续持有或卖出平仓。 |
| 信号与成交 | 信号使用当根日线收盘后可见的数据，成交安排在下一根日线 bar，避免按刚形成信号的同一收盘价成交。 |
| 资金与份数 | 初始资金为人民币 100,000 元；信号开启时尽量使用可用资金，下单份数向下取整到 100 份，余款留在现金中。 |

这只是简单的趋势示例，没有完整的左侧、右侧、震荡市判断，也没有经过项目确认的策略有效性结论。回测跑通或某一段历史盈利，都不能证明未来会赚钱。

## 4. 回测成本怎么理解

当前每次成交按单边佣金率 `0.00005` 计算，单次最低收人民币 0.1 元；买入和卖出分别计佣金。默认 `spread=0.0005` 是回测框架使用的固定成本假设，不是 563360 的实测点差，也不是实测滑点；实际交易成本还可能受券商费率、流动性和成交方式影响。

修改 `--spread` 只是在模型里换一个假设，不会让回测成本变成真实市场数据。比较结果时，务必同时记下日期区间、标的和成本设置。

## 5. 去哪里看结果

默认情况下，程序在 `results/` 下生成三类文件：

- `result.json`：本次标的、日期、策略周期、资金和成本假设，以及汇总指标。
- `equity.csv`：回测期间的账户权益曲线，可用表格软件或 Python 查看。
- `trades.csv`：逐笔已产生的交易记录。

JSON 中常见指标：

- `total_return`：整个回测区间的总收益率，以小数保存；例如 `0.1` 表示 10%。
- `profit_factor`：盈利交易总额除以亏损交易总额的绝对值。若没有亏损交易、无法计算，值为 `null`，不表示程序出错。
- `max_drawdown`：权益曲线从此前高点到之后低点的最大跌幅，以小数保存；例如 `-0.2` 表示最大回撤为 20%。
- `trade_count`：已平仓交易笔数。
- `mean_holding_period`：已平仓交易平均持有的日线 bar 数；配套的 `mean_holding_period_unit` 为 `trading_day_bars`。这不是自然日数。

收益、回撤和交易指标都是在指定历史数据及模型假设下计算出来的，不是未来收益预测，也不自动考虑所有现实交易约束。

## 6. 常见问题

**提示找不到完整缓存，怎么办？** 先确认 ETF 代码和日期，再按 README 的说明，用相同标的及覆盖所需日期的 `--refresh` 命令刷新。普通模式不会自动补数据。

**行情已经缓存，为什么还要因子和交易日历？** 项目会用因子把 OHLC 价格做前复权，并检查缓存行情是否覆盖日历中的预期交易日。所需因子或交易日对不上时会停止，不会悄悄改用未复权数据或填补缺口。

**改了日期后缓存还能用吗？** 只有在已保存缓存的覆盖范围内、且该范围内预期交易日齐全时才能用。日期超出缓存范围时需要重新显式刷新。

**可以一次回测多只 ETF 吗？** 不可以。一次运行只处理一只 ETF；目前没有组合资金分配、仓位再平衡或跨标的管理。

**可以用它自动买卖或接收信号吗？** 不可以。项目只做离线历史回测，没有券商连接、实盘下单或信号推送。

**这是不是最终波段策略？** 不是。当前 SMA(20/60) 仅用于验证工程流程；项目还没有定稿或验证左侧、右侧、震荡等完整策略。
