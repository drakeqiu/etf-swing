# 使用指南：从准备环境到读懂回测结果

这份指南面向第一次运行项目的人。跟着步骤做，可以在本地准备环境、拉取一段 ETF 日线数据、运行示例回测，并找到结果文件。

> **先说明项目边界：**这是一个单只 ETF 的日线回测工程骨架，不是已经验证有效的波段策略。它不会下实盘订单、连接券商或推送买卖信号。文中的 SMA 规则只是用来检查行情到回测再到结果导出的整条流程，不是投资建议。

## 1. 先准备好这些东西

- 一台能运行 Python 的电脑。
- Python 3.14 和 `uv`。仓库通过 `.python-version` 指定 Python 3.14；项目依赖中包含仓库提供的本地 wheel，安装时不要把 `wheels/` 目录删掉。
- 若要刷新行情：可用的 AmazingData 本机环境、账号、密码、主机地址和端口，以及访问行情数据所需的权限。没有这些也可以读取别人已经准备好的完整本地缓存，但缓存需要与要回测的标的和日期范围相符。
- 一个终端，并在终端切换到项目仓库根目录，也就是能看到 `pyproject.toml` 的目录。

## 2. 安装项目环境

在项目根目录运行：

```sh
uv sync
```

这会根据项目配置准备 Python 环境和依赖。若电脑没有可用的 Python 3.14，先安装 Python 3.14，再重试。仓库包含 AmazingData 与 `tgw` 的本地 wheel；如果安装提示找不到 wheel，请确认文件仍在 `wheels/` 目录下。

## 3. 准备行情刷新凭据

只有要从 AmazingData 刷新行情时才需要账号凭据。在项目根目录创建本机 `.env` 文件，写入下面四项，并把示例值换成你的真实信息：

```dotenv
AMAZINGDATA_USERNAME=你的用户名
AMAZINGDATA_PASSWORD=你的密码
AMAZINGDATA_HOST=你的服务主机
AMAZINGDATA_PORT=你的服务端口
```

不要把真实凭据贴到聊天、提交到 Git 或写进文档。`.env` 已被 Git 忽略。普通缓存回测不登录 AmazingData，也不需要 `.env`；刷新时才会读取这些变量。

## 4. 第一次运行：刷新行情并回测

先选好标的和起止日期，然后在项目根目录执行：

```sh
uv run --env-file .env etf-swing \
  --symbol 563360 \
  --start 2024-01-01 \
  --end 2025-12-31 \
  --refresh
```

把 `563360` 换成你要研究的单只 ETF 代码，把日期换成所需区间。日期必须写成 `年-月-日`，例如 `2024-01-01`。起始日期不能晚于结束日期。

`--refresh` 的意思是“这次明确去刷新行情”。程序会在命令行运行边界登录 AmazingData，查询日线行情、复权因子和交易日历，检查行情日期与因子日期是否能对应，再运行回测并保存缓存。命令结束后会登出。

刷新得到的行情和配套数据放在 `data/cache/`。这是本地运行数据，不应提交到 Git。缓存覆盖范围由这次刷新请求决定；之后只能对缓存覆盖的日期范围做普通回测。要增加范围或更新数据，再对需要的日期区间运行一次带 `--refresh` 的命令。

## 5. 后续运行：只用本地缓存

缓存已经覆盖目标标的和所需日期时，可以不加 `--refresh`，也不必加载 `.env`：

```sh
uv run etf-swing \
  --symbol 563360 \
  --start 2024-01-01 \
  --end 2025-12-31
```

普通运行只读取本地缓存，不会联网、登录或自动补数据。缓存不存在、不完整、日期范围超出缓存覆盖范围，或者行情交易日与缓存日历对不上时，程序会报错停止。遇到这种情况，检查标的和日期；确实需要新数据时再显式加 `--refresh`。不要把普通运行理解成“自动下载缺失数据”。

## 6. 常用命令参数

| 参数 | 用途 | 默认值或要求 |
| --- | --- | --- |
| `--symbol` | 指定单只 ETF | `563360` |
| `--start` | 回测起始日期 | 必填，`YYYY-MM-DD` |
| `--end` | 回测结束日期 | 必填，`YYYY-MM-DD` |
| `--refresh` | 明确刷新行情、因子和交易日历缓存 | 默认不刷新 |
| `--spread` | 修改回测框架使用的固定 spread 成本假设 | `0.0005`，也就是 0.05% |
| `--cache-dir` | 指定行情缓存目录 | `data/cache/` |
| `--output-dir` | 指定结果输出目录 | `results/` |

例如，把结果放到另一个目录并使用不同 spread 假设：

```sh
uv run etf-swing \
  --symbol 563360 \
  --start 2024-01-01 \
  --end 2025-12-31 \
  --spread 0.001 \
  --output-dir results/test-run
```

如果这个日期范围没有对应的完整缓存，普通命令会失败；需要先按第 4 步刷新。

## 7. 现在实际运行的是什么策略？

项目当前用 SMA(20/60) 做示例。“SMA”就是简单移动平均线：把最近若干个交易日的收盘价加起来，再除以天数。

| 规则 | 行为 |
| --- | --- |
| 快线 | 最近 20 个交易日收盘价的平均值。 |
| 慢线 | 最近 60 个交易日收盘价的平均值。 |
| 快线高于慢线 | 策略从空仓转为持有该 ETF；已有持仓时继续持有。 |
| 快线不高于慢线 | 若有持仓就平仓；若已经空仓就继续空仓。 |
| 仓位方向 | 只做多，不做空、不加杠杆；没有持仓时买入，有持仓时只能继续持有或卖出平仓。 |
| 信号与成交 | 信号使用当根日线收盘后可见的数据，成交安排在下一根日线 bar，而不是假定能按刚形成信号的同一个收盘价成交。 |
| 资金和份数 | 初始资金为人民币 100,000 元。信号开启时尽量使用可用资金，下单份数向下取整到 100 份；没用上的钱继续留在现金里。 |

这只是一个简单的趋势示例，没有完整的左侧、右侧、震荡市判断，也没有经过项目确认的策略有效性结论。回测跑通或某一段历史盈利，都不能证明未来会赚钱。

## 8. 回测成本怎么理解

当前每次成交按单边佣金率 `0.00005` 计算，单次最低收人民币 0.1 元；买入和卖出分别计佣金。默认 `spread=0.0005`，是回测框架使用的固定成本假设。它不是 563360 的实测点差，也不是实测滑点；实际交易成本还可能受券商费率、流动性和成交方式影响。

修改 `--spread` 只是在模型里换一个假设，不会让回测成本变成真实市场数据。比较结果时，务必同时记下日期区间、标的和成本设置。

## 9. 去哪里看结果

默认情况下，程序在 `results/` 下生成三类文件：

- `result.json`：本次标的、日期、策略周期、资金和成本假设，以及汇总指标。
- `equity.csv`：回测期间的账户权益曲线，可用表格软件或 Python 查看。
- `trades.csv`：逐笔已产生的交易记录。

JSON 中常见指标：

- `total_return`：整个回测区间的总收益率，以小数保存；例如 `0.1` 表示 10%。
- `profit_factor`：盈利交易总额除以亏损交易总额的绝对值。若没有亏损交易、无法计算，值为 `null`，不表示程序出错。
- `max_drawdown`：权益曲线从此前高点到之后低点的最大跌幅，以小数保存；例如 `-0.2` 表示最大回撤为 20%。
- `trade_count`：已平仓交易笔数。
- `mean_holding_period`：已平仓交易平均持有的日线 bar 数；配套的 `mean_holding_period_unit` 为 `trading_day_bars`。这不是自然日数。

收益、回撤和交易指标都是在指定历史数据及模型假设下计算出来的，不是未来收益预测，也不自动考虑所有现实交易约束。

## 10. 常见问题

**提示找不到完整缓存，怎么办？** 先确认 ETF 代码和日期，再用相同标的、覆盖所需日期的 `--refresh` 命令刷新。普通模式不会自动补数据。

**行情已经缓存，为什么还要因子和交易日历？** 项目会用因子把 OHLC 价格做前复权，并检查缓存行情是否覆盖日历中的预期交易日。所需因子或交易日对不上时会停止，不会悄悄改用未复权数据或填补缺口。

**改了日期后缓存还能用吗？** 只有在已保存缓存的覆盖范围内、且该范围内预期交易日齐全时才能用。日期超出缓存范围时需要重新显式刷新。

**可以一次回测多只 ETF 吗？** 不可以。一次运行只处理一只 ETF；目前没有组合资金分配、仓位再平衡或跨标的管理。

**可以用它自动买卖或接收信号吗？** 不可以。项目只做离线历史回测，没有券商连接、实盘下单或信号推送。

**这是不是最终波段策略？** 不是。当前 SMA(20/60) 仅用于验证工程流程；项目还没有定稿或验证左侧、右侧、震荡等完整策略。
